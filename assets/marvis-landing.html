// ring buffer — screen frames live in memory only const HORIZON: Duration = Duration::from_secs(60); const MAX_FRAMES: usize = 120; // ≤ 64 MB cap fn on_ask(&self, prompt: String) { let frame = self.ring.latest(); self.llm.stream(prompt, frame); // never hits disk } fn lock(&mut self) { self.capture.stop(); // tear down capture self.panels.hide_all(); // hide every panel self.requests.abort_all(); // cancel in-flight asks }

Why does ring.latest() return None on launch?

The buffer only fills after the first captured frame lands — once Screen Recording is granted. Until then, latest() is empty by design: Marvis never keeps frames from before you asked.

What's different

Built like part of your desktop, not a tab you visit.

Screen-aware answers

Press ⌘⏎ and Marvis attaches the latest screen frame to your prompt, then streams a markdown answer into the panel. Frames sit in an in-memory ring buffer — about 60 seconds, capped at 120 frames — and are never written to disk.

Bring your own model

Point Marvis at OpenAI, Anthropic, or Gemini with your own API key — or skip keys entirely and run fully local inference through Ollama. There's no Marvis account and no proxy in the middle.

Your keys stay sealed

Provider keys live in keys.enc, encrypted with AES-256-GCM under a passphrase-derived Argon2id key and validated before they're stored. The UI only ever sees masked values.

The interface

One bar, three panels — nothing else.

Recreated 1:1 from the app's own views: a 353×47 bar, a 600px Ask panel, a 400px Listen panel, and a 240px Settings panel — frameless, frosted overlays, not browser windows. The toggle swaps in the app's real dark theme.

Settings, 240px wide

Provider keys, masked.

Keys are validated against the provider before they're stored, then only ever shown as …last4. Ollama needs no key — it talks to the local daemon. Deepgram lands with Listen in Phase 2.

Docks off Ask's left edge.

Local-first architecture

What's on your machine stays on your machine.

No accounts, no sync service, no Marvis servers. The only thing that ever leaves your device is the request you send — your prompt plus one screen frame — straight to the LLM provider you chose.
